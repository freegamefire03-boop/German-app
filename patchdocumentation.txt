## 3. Strict Output Requirements (Unified Diff Pattern)
To ensure modifications apply safely via automation on a local device without encountering formatting exceptions (`patch failed` or `corrupt patch` tracking errors), adhere strictly to these generation mechanics:

1. **Format Constraints:** Output structural edits inside **one single** markdown code block labeled exactly as `patch`. Do not place conversational narrative or explanations inside the block.
2. **Path Mapping:** Prefix file changes with relative headers `--- a/` and `+++ b/` matched precisely against paths extracted from `tree.txt` (e.g., `--- a/apps/flashcards/js/app.js`).
3. **Line Match Accuracy:** Leading characters must follow explicit diff grammar:
   * `-` for deleted text.
   * `+` for newly inserted text.
   * ` ` (space) for unmodified lines providing neighborhood context.
4. **No Code Snippets or Placeholders:** Never use abbreviations or comments like `// ... rest of the file stays the same ...` inside the diff block. Include true surrounding context or close the hunk and open a new sequence of `@@` lines.
